# Automatic board material 002 — Count on

Base: verified `f1a3e1cb2ee2cda188e24044cccd18e938033a11`, including the fixed fullscreen exit. Work branch: `preview/mission-auto-count-on-20260924`. No production promotion.

Read-only comparison on 2026-09-24 found the remote group branch still at `d13f1321f9316f27830b2d46cc4a18c314ce054c`; the fullscreen branch adds exactly one commit. Latest preview deployment was `dpl_74m68M4HvgrsTt66aLEoHGUMoHXX` (READY). The older local mission checkout contains audio/diagnostics build transformations, not another automatic Count on implementation; it is left untouched. Existing `count-on-clip.mjs` and the prepared 8+2 package are historical examples, not automatically generated-number materials.

This increment adds only the existing generated Count on question. `countOnData(step)` binds the starting number, extra counters, individual forward steps, final equation and EN/FR narration to the same generated numbers. The initial board shows the starting point, a number line and the extra counters with `= ?`. After an answer or explicit solution request, those same counters move one at a time to their forward-step positions. It is an on-device SVG animation, with no additional media controls or external media/AI requests.

Language changes alter the labels and narration only. Saved material state is keyed by existing session ID and exact numbers, separately from the lesson state. Question input stops motion; the existing dialogue return or Continue resumes that position. Teacher pauses remain paused. Reload restores the frame paused. New lesson retains the existing generator and confirmation, and receives a new material key. Next does not create a session. Storage remains same-origin, same-device/browser and subject to browser storage availability.

The build entry is now `node mission/build-count-on.mjs`, which imports the entire preserved `build-fullscreen-exit.mjs` chain before adding this material. No previous gate is bypassed. `patch-count-on.mjs` checks each final-runtime anchor before applying the narrow integration. Both materials repaint their shared heading/fact when reactivated; this is the only adjustment to the built JOIN module. The existing fullscreen controller and lesson generator are unchanged. The service-worker cache is advanced and includes the added local module.

Validation: pure tests cover 70 supported number pairs and 1,470 intermediate frames. Browser tests use the real existing VRM with simulated speech synthesis/recognition. They check answer visibility, text/voice receipt, numeric questions, correction hold, question/20-second return, teacher-paused return, EN/FR preservation, reload, new/continue/next distinctions, JOIN transition and portrait/landscape fullscreen X. Existing dialogue and fullscreen suites run again against the final extended runtime. Physical Samsung/iPhone TTS/microphone quality and full-classroom use require operator confirmation. No claim of offline free dialogue, cross-device synchronization or universal AI correctness.

Make ten and Missing number to ten are not changed by this increment. No third-party student resource is imported; the diagrams are original and generated from the current arithmetic.

Builder timing hardening: the Count on SVG clock uses a lightweight 50 ms timer, independent of WebGL frame callbacks, and still stops for paused/hidden/dialogue states. The mid-animation interruption test observes progress and delivers its input event in the same browser task, avoiding a race where slow automation round trips allow the short animation to finish before the test asks its question. All progress, freeze, return and session assertions remain mandatory; failures include the bounded media state for diagnosis.

The interruption observer is installed before Send, because a software-rendered builder may deliver the click's protocol response only after the animation. A deliberate 6.5-second post-click delay tests this case. The observer only fills the existing input and dispatches its normal input event; it does not edit lesson or animation state. The existing Send handler, follow-up timer and Continue logic are then tested normally. Timeout diagnostics report current material/phase/focus/speech state without credentials or student records.

The existing group timer caps each elapsed interval at one second. On software-rendered CI, its 20-second follow-up can therefore exceed 30 wall-clock seconds. The teacher-paused follow-up test permits 90 wall-clock seconds while still requiring automatic dialogue completion and unchanged paused lesson/frame; no runtime timer or gate is removed. Failure diagnostics include visible countdown, voice status, and unresolved state.
