# Programme Next button: strict submitted-choice recognition

Base: e33eed9f0ae540497be8b05f37b21c0a80f80b1a, the user's current AI-workbook deployment. Work is isolated on fix/mission-next-20260925. Main, the original workbook branch and the confirmed Grade 2 sample are not overwritten.

Root cause: the screenshot's recognized input is `see he might come to the party`, corresponding to `C. He might come to the party.` The old choiceFor accepted only a bare A/B/C or exact option text. The combined spoken label + content therefore entered general AI chat. The chat answer could explain the right choice, but did not set revealed/choices; Next intentionally remained disabled. This was not a failure of the microphone or Next click handler.

Only existing runtime change: programme/core.mjs choice recognition. A bare label, the full displayed choice, affirmative selection wrappers, or a matching label plus the full choice share the same deterministic answerChoice path. Common letter-name transcription variants are recognized in the existing multiple-choice input context. Prefix and repeated content must agree. No fuzzy/substring matching, no extra AI grading call, no accepting conflicting labels, no grading ordinary questions such as Why C? Numeric comparison preserves decimal points, signs and units. The existing lesson validation and content-exclusion code is unchanged.

The existing Next gate and answerChoice behavior are preserved: submitted answers show feedback and enable manual Next, including an incorrect answer after the correction is shown. The lesson remains paused for teacher review and is not advanced automatically. General questions are still general questions and do not mark an unanswered question complete. Paraphrases that do not identify a unique displayed choice still require choosing A/B/C or tapping a choice; no semantic omniscience is claimed.

No changes to audio tools, opt-in cloud speech, transcription history, avatar, programme app, workbook engine, server endpoints, fullscreen, language switching, session keys, cache versions, generation rules or build entrypoint. The unchanged deployment build retains all inherited tests. New focused tests reproduce the old disabled-Next state and verify the fix through the real programme/workbook app and speech-input tools; device speech, avatar and AI replies are simulated in that focused test. The unit suite covers 53 selection/ambiguity/number cases. Full device microphone accuracy is not certified.
