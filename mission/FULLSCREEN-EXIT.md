# Mobile fullscreen exit only — fullscreen-exit-v1

Base snapshot: d13f1321f9316f27830b2d46cc4a18c314ce054c, the saved and deployed dialogue classroom. Work is isolated on fix/mission-fullscreen-exit-20260924. Do not update preview/global-mission-group-20260924 or main as part of this repair. Other-window work and existing deployment aliases remain untouched.

The previous controller gated every click, including exit, behind a pending entry promise. A native fullscreen event did not release that guard. An unresolved or delayed request promise could therefore leave the visible Exit inert. The former exit control was also inside a scrollable page header. These source-level failure cases were checked; the precise physical-phone event sequence was not observed.

The display-only controller now keeps a 48px touch exit (X) fixed at the top-right whenever presentation mode is active. The normal classroom does not show this extra control. The original full-screen toggle also remains usable. Native events and actual fullscreen state, not only promise completion, control entry and exit. Closing is allowed during entry; stale callbacks cannot reopen page expansion; prefixed WebKit methods are supported. Exit rejection/timeouts keep a retry control and an honest status, never falsely reporting that the browser left native fullscreen. No changes to browser history, permissions or recording behavior are made.

Leaving full screen restores the prior view and scrolling. The new code does not mutate questions, answers, lesson timing, automatic materials, session IDs, draft text, language, voice consent, microphone logic, AI instructions or API routing. The 3D model and renderer remain unchanged. The service-worker cache version is bumped to deliver the updated display code.

The existing full regression build remains mandatory. The additional final-runtime tests exercise native touch exit in portrait/landscape/short viewports, scrolling, rotation, French labels, and the original exit toggle. They compare draft, problem, timing, pause and dialogue state before and after. Separately, a local display fixture tested stalled-entry promises, event-only exit completion, prefixed WebKit methods, refused/stalled exit recovery, canceled late entry and label restoration using simulated API timing. Those fixture tests are not a physical browser-device measurement. Phone dimensions and touch in the build are browser-emulated; physical Samsung/iPhone confirmation is still needed. No extra AI or speech-provider test calls are added.
