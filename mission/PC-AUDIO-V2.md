# PC audio repair v2

Scope: an isolated fix branch based on d1ad581990329ffde0b01c6712123fe29ecbec6b. The English/French approved sample, question generation, numeric geometry, five language translations, AI endpoints and fullscreen-exit implementation are preserved. Only the PC speech controls and their input-display integration change. No new audio recording upload, cloud speech endpoint, credentials, paid provider or automatic language fallback is added.

Confirmed source defect: PC recognition used interimResults=false, wrote a final transcript, immediately submitted it, and erased the input on success. This could make a working recognition appear not to fill the input. The patch displays interim hypotheses without submitting them, holds a final transcript visibly for 750 ms, auto-submits it once, and preserves sent voice text plus a receipt. Typing or switching language cancels a queued transcript; late callbacks cannot affect the new language/problem. Stop requests a final result and leaves interim-only text for manual Send. Existing manual text submission remains available. Sent text is distinguished from an unsent draft so it does not block lesson continuation; a refresh restores that distinction in the existing PC session storage.

Other reported issue: no teacher voice in Nepali, Urdu or Swahili. This is not established to be a microphone failure. Reading uses voices actually exposed by speechSynthesis.getVoices; recognition uses a separate service. Audio settings now show local/online voice counts and consent, last synthesis state, and last actual recognition outcome separately for each language. Errors retain permission/network/language-not-supported/audio-capture/no-speech distinctions. Zero voices is not proof that the speech-recognition service rejects that language, and a completed playback event is not certification of audible speaker output. No voice is fabricated or silently replaced by an English voice. A delayed matching voice list can resolve one pending request within four seconds; explicit pause/language change cancels it. Browser-online voice consent and selection are stored per language. Enabling it does not install absent voices.

Windows' current standard TTS listing does not include Nepali, Urdu or Swahili; however third-party voice exposure and browser recognition support must be checked on the actual PC. No claim that all five languages now have physical-device audio. References: https://support.microsoft.com/en-us/accessibility/windows/narrator/appendix-a-supported-languages-and-voices ; https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices ; https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition/interimResults ; https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognitionErrorEvent/error .

Checks: local module fixture exercised all five transcript scripts, delayed one-shot sending, edit/language cancellation, interim-only stop, error preservation, per-language online consent and late voice lists. Final build runs the entire unchanged baseline chain and then the repaired PC application with a real VRM and simulated speech services. It also checks same-problem reload, diagnostic data, and fullscreen exit. The fixture and headless tests cannot certify the user's microphone, speaker, or service-language coverage. Diagnostics are local technical state, not an uploaded student conversation log.
